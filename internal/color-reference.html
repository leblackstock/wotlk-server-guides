Color hierarchy

FoundationSurfaces, text, borders
Section or classBroad identity
SpecializationActive state and focus
MechanicRepeated gameplay concept
Status or game dataFixed global meaning
Primary rule: use the highest-level color that accurately describes the information. Do not invent a local accent when an existing semantic role already fits.

Adding or revising a guide

1. Establish the class

Choose one class identity that survives every specialization.

2. Keep the class together

Document every specialization on one class page before splitting any supporting implementation documents.

3. Audit before retaining

Existing colors are candidates, not truth. Check collisions, contrast, semantics, and family separation before approval.

4. Name mechanics

Use two to four repeated concepts instead of coloring individual abilities.

5. Protect fixed meanings

Warning, danger, success, information, rarity, and sockets never become decoration.

6. Reconcile after launch

Once a guide is live, compare production components against this reference and fold real implementation rules back into the class page.

Fixed meanings

Success

Confirmed compatibility, completed requirements, safe positive state.

--status-success
Warning

Risk, caution, provisional behavior, or a meaningful tradeoff.

--status-warning
Danger

Failure, breakage, lethal mistakes, or destructive actions.

--status-danger
Information

Neutral factual callouts, not a substitute for a specialization or mechanic identity.

--status-info
